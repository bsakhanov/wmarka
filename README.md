# Wmarka 4.0.13 — стартовый шаблон для Joomla 5 и 6 на UIkit 3

*English version: [README.en.md](README.en.md)*

Wmarka — бесплатный стартовый шаблон для Joomla 5 и 6, построенный на UIkit 3.25 без Bootstrap. Он годится и для новостного сайта, и для сайта компании: все настройки собраны в стиле шаблона, разметка штатных страниц Joomla переписана на компоненты UIkit, а демо-сайт «Вестник» ставится одним пакетом.

- Репозиторий: <https://github.com/bsakhanov/wmarka>
- Демо: <https://site.webmarka.kz>
- Разработчик: Webmarka · Бейбит Саханов, <https://webmarka.kz>
- Лицензия: GNU GPL версии 2 или новее

## Что входит в пакет

Полная установка — один архив **`pkg_wmarka-4.0.13.zip`**. В нём пять расширений, они ставятся в таком порядке:

| Расширение | Что это | Зачем |
|---|---|---|
| `lib_juimage` 5.21 | библиотека JUImage (Denys Nosov, Joomla! Ukraine) | режет превью и переводит их в WebP |
| `tpl_wmarka` 4.0.13 | сам шаблон | всё оформление сайта |
| `tpl_wmarka_vestnik` 1.0.0 | дочерний шаблон демо-сайта | пример дочернего шаблона по правилам Joomla |
| `com_blank` 2.0.1 | компонент «Пустая страница» (Alek Volsk, Sergey Tolkachyov) | страницы, собранные из модулей: главная, лендинги |
| `plg_sampledata_wmarka` | установщик образцов данных | разворачивает демо-сайт «Вестник» |

Шаблон можно поставить и отдельно — архивом **`tpl_wmarka-4.0.13.zip`**. Тогда JUImage и com_blank ставятся по желанию: без JUImage картинки выводятся оригиналами, без com_blank главную из модулей придётся строить иначе.

## Требования

- Joomla 5.0 и новее, проверено на Joomla 6.1.4;
- PHP 8.1 и новее;
- для превью — расширение PHP GD с поддержкой WebP (на большинстве хостингов оно есть);
- включённые ЧПУ и `.htaccess` — для красивых адресов и умного поиска по адресу `/search`.

## Установка

### Вариант 1. Полная демо-установка

Подходит для знакомства с шаблоном и для нового сайта «с нуля».

1. Поставьте чистую Joomla 5 или 6.
2. **Система → Установка расширений → Загрузить файл пакета** → `pkg_wmarka-4.0.13.zip`. Пакет поставит JUImage, шаблон, дочерний шаблон, com_blank и установщик демо, включит компонент и установщик.
3. **Система → Образцы данных** (на панели управления — блок «Образцы данных») → **Демо-сайт wmarka → Применить**. Шесть шагов идут по очереди; каждый пишет, что сделал.
4. Откройте сайт: главная, новости, мегаменю, страница «Позиции модулей» уже на месте.

Демо меняет стиль шаблона и общие опции материалов, меток и контактов. Ставьте его на чистую Joomla, а не на рабочий сайт. Повторный запуск безопасен: записи ищутся по ключу и обновляются, дублей не появляется.

### Вариант 2. Только шаблон

1. Поставьте `tpl_wmarka-4.0.13.zip`.
2. При желании поставьте JUImage (из пакета или с <https://github.com/Joomla-Ukraine/JUImage>) и com_blank.
3. **Система → Стили шаблонов сайта → wmarka → По умолчанию**.
4. Пройдите [первые шаги](#первые-шаги-после-установки).

### Вариант 3. Обновление с 3.0.x

Поставьте новый архив поверх старого — «Установка расширений» сама обновит шаблон. Что происходит при обновлении — в разделе [«Обновление»](#обновление).

## Первые шаги после установки

Все настройки — в стиле шаблона: **Система → Стили шаблонов сайта → wmarka**. На первой вкладке есть карточка «Состояние шаблона». Она показывает версии шаблона и UIkit, найдена ли JUImage, есть ли `user.css`, сколько превью в кэше.

1. **Общие:** название и слоган, логотип (картинка, текст или оба), ширина контейнера, шрифт.
2. **Контакты:** телефон, почта, WhatsApp, Telegram, адрес, карта, часы работы. Они попадут в тулбар, мобильную панель, подвал и микроразметку.
3. **Шапка и навигация:** вариант шапки, липкий навбар, кнопка действия, пункт меню поиска.
4. **Изображения:** проверьте, что JUImage включена, и задайте размеры превью.
5. **SEO:** название и тип организации, адрес, соцсети, картинка для соцсетей по умолчанию.
6. **Меню:** опубликуйте модуль меню в позиции `navbar-right` (или `navbar-left`). Мобильная панель скопирует его сама.
7. **Поиск:** создайте пункт меню «Умный поиск» с алиасом `search` (можно в скрытом меню) и выберите его в настройке «Пункт меню поиска».

## Позиции модулей

Шаблон объявляет 37 позиций. Страница «Позиции модулей» демо-сайта показывает каждую: в каждой стоит модуль с подписью.

| Позиция | Где выводится |
|---|---|
| `toolbar`, `toolbar-left` | тулбар слева |
| `toolbar-right`, `lang` | тулбар справа (языки — отдельно) |
| `head-banner` | над шапкой, во всю ширину |
| `logo` | вместо логотипа из настроек |
| `headbar` | справа от логотипа в шапке «логотип над меню» |
| `navbar-left`, `navbar-center`, `navbar-right` | навбар |
| `iconnav` | иконки в навбаре |
| `login` | окно под иконкой пользователя |
| `offcanvas-menu`, `offcanvas` | мобильная панель: меню и модули |
| `breadcrumb` | хлебные крошки (без модуля шаблон строит их сам) |
| `adver-top` | под шапкой, над контентом |
| `slider` | слайдер или обложка |
| `block-a`, `block-b` | блочные позиции над контентом |
| `main-top`, `main-bottom` | над компонентом и под ним, в колонке контента |
| `sidebar-a`, `sidebar-b` | левый и правый сайдбары |
| `block-c` … `block-k` | блочные позиции под контентом |
| `footer-left`, `footer-center`, `footer-right` | колонки подвала (без модуля в `footer-right` выводятся контакты) |
| `footer` | строка копирайта |
| `counters` | скрытая позиция для кодов счётчиков |
| `debug` | отладка, самый низ страницы |

### Как работают блочные позиции

Все блочные позиции (`block-a` … `block-k`) выводит один метод `Helper::block()`, отдельного файла на каждую нет. Правило одно:

- **все модули позиции со стилем `blank`** — позиция выводится как есть, без обёртки. Модуль сам приносит полноширинную секцию (`<section class="uk-section …">`). Так делаются обложки, видеоблоки, призывы, подписка;
- **иначе** шаблон оборачивает позицию сам: секция `uk-section` (фон, отступы, чередование — из настроек), контейнер, сетка `uk-grid` с числом колонок по числу модулей (не больше четырёх) или по настройке «Колонок в блочной позиции».

Суффикс класса модуля `uk-width-…` перебивает ширину колонки. Например, `uk-width-2-3@m` у одного модуля и `uk-width-1-3@m` у другого дают раскладку «две трети и треть».

## Меню и мегаменю

Мегаменю включается токенами в поле **«CSS-класс ссылки»** пункта меню первого уровня в навбаре.

| Токен | Что делает |
|---|---|
| `wm-mega` | выпадающая панель; колонки — подпункты пункта, ссылки — их дети |
| `wm-mega:тип_меню` | выпадающая панель из вспомогательного меню: пункты первого уровня — колонки, их дети — ссылки |
| `wm-mega-modal:тип_меню` | то же во весь экран: колонка — секция, каждый пункт — карточка с иконкой и примечанием |
| `uk-icon:имя` | иконка UIkit перед названием (`uk-icon:camera`, `uk-icon:grid`…) |
| `wm-icon-only` | только иконка, название скрыто (остаётся для экранных читалок) |
| `wm-mod-ID` | в колонке выводится модуль с этим ID (модуль должен быть опубликован в любой позиции, например `mega`) |
| `wm-invert` | тёмная колонка |
| `wm-col-footer` | ссылка уходит в подвал колонки |

**Как собрать мегаменю из вспомогательного меню:**

1. Создайте меню, например `news-mega`. Модулем его не выводите.
2. Пункты первого уровня — колонки. Удобнее всего тип «Заголовок». В поле «Примечание» напишите подзаголовок колонки.
3. Их дети — ссылки. Лучше всего тип «Псевдоним» на настоящие страницы: адреса останутся чистыми, активный пункт подсветится.
4. В главном меню у пункта «Новости» впишите в «CSS-класс ссылки» `wm-mega:news-mega`.
5. Для окна во весь экран: `wm-mega-modal:template-mega`. Примечание главного пункта станет заголовком окна, примечания ссылок — подписями карточек.

### Главная страница

Главной шаблон считает только собственную страницу главного пункта меню — его `option`, `view` и `id`. Если главный пункт — блог категории, материалы открываются через него же, но главной не считаются: у них свой canonical, хлебные крошки, заголовок и ссылка на логотипе, а токены главного пункта (`wm-blank`) на них не действуют. Для этой схемы нужны две настройки, и обе по умолчанию стоят в положении «Авто»: «Блоки главной — только на главной» (вкладка «Макет») прячет слайдер и блоки главной вокруг материалов, а «Canonical: режим» склеивает адреса материала. «Авто» включает их, когда главный пункт — блог категории или избранные материалы; карточка «Состояние шаблона» показывает, что действует.

### Токены страницы («CSS-класс страницы» пункта меню)

- `wm-blank` — страница без компонента, только модули (главная из блоков);
- `wm-wide` — компонент во всю ширину, без сайдбаров.

## Материалы, блог, метки, авторы

### Вкладка «Опции WMARKA» в пункте меню

У пунктов «Блог категории», «Избранные материалы» и «Метка» есть своя вкладка:

- вид по умолчанию: сетка или список;
- переключатель «сетка / список» для посетителя (выбор запоминается);
- масонри;
- зазор между карточками;
- стиль карточки: белая, тёмная, акцентная, без рамки;
- положение картинки: сверху, снизу, слева, справа, чередовать;
- тень при наведении;
- анонс в карточках (символов), ведущие материалы — целиком.

Карточки собраны на компоненте Card UIkit. Сверху — `uk-card-media-top`; слева и справа — горизонтальная карточка с `uk-cover`; без картинки — `uk-card-body`.

### Опции ядра работают

Шаблон не подменяет штатные опции Joomla: колонки, «Максимум символов» меток, изображения и описания в списках меток, «Значки или текст» в контактах, обтекание изображения полного текста, положение служебной строки — всё это действует. Шаблонные опции добавлены там, где у ядра своих нет.

### Метки

- «Метка» — карточками (`default`) или таблицей (`list`, с миниатюрами);
- «Все метки» — сеткой карточек, «Каталог меток» (`wm-catalog`, с фильтром), «Карта меток и рубрик» (`wm-tree`, деревья меток и категорий).

### Авторы

Автор материала — пользователь Joomla, у которого есть контакт (в контакте выбран «Связанный пользователь»). Тогда:

- подпись в статье ведёт на страницу контакта;
- страница контакта выводит все материалы автора (опция контакта «Показывать материалы»);
- под статьёй выводится карточка автора: фото, должность, «Все материалы автора».

Макет категории контактов «Команда» (`wm-team`) показывает авторов карточками с круглыми фото.

## Новостная подача

Подача сделана по образцу новостных сайтов РК (zakon.kz, nur.kz, baq.kz) — только классами UIkit:

- **рубрика** строкой над заголовком в карточке и статье;
- **дата** по-новостному: «Сегодня, 14:32», «Вчера, 18:50», «2 октября, 17:14»; в статье — «18:11, 2 октября 2026»; в ленте — одно время (настройка «Подача даты»);
- **метки** в карточках — хэштегами в служебной строке, в статье — плашками в конце (`uk-button-small uk-border-pill`);
- **видео- и фотоновости** — значок воспроизведения или фотоаппарата поверх картинки. Метки задаются настройками «Метка видеоновостей» и «Метка фотоновостей» (по умолчанию алиасы `video` и `foto`);
- **лид**: первый абзац статьи получает `uk-text-lead`;
- **цитата** (`<blockquote>` с `<footer>` для подписи) — крупный глиф кавычки подложкой и бледный фон;
- **«Поделиться»** — WhatsApp, Telegram, Facebook, X, простыми ссылками без сторонних скриптов;
- **видео с YouTube** в тексте (`<iframe>` с `width` и `height`) становится адаптивным само; у видеоновости обложка не дублирует плеер;
- **фотогалерея** — разметка `uk-lightbox` в тексте материала.

## Изображения

Нужна библиотека JUImage — она в составе полного пакета. Без неё сайт работает, но выводит оригиналы.

- **Одно превью на картинку.** Карточки блога и избранного, страницы меток, поиск и все модули берут один и тот же интро-файл. Полное изображение статьи — второй размер, на телефоне вместо него показывается тот же интро-файл. Для соцсетей — JPG 1200 × 630.
- **Достаточно вступительного изображения.** Если поле «Изображение полного текста» пустое, статья покажет вступительное. Если пусты оба, шаблон возьмёт первую картинку из текста, а при её отсутствии — заглушку.
- **srcset без лишних файлов.** Интро (720w) и полное (1200w) — один кадр в двух размерах, поэтому карточки получают `srcset` из этих двух файлов и `sizes` по раскладке. Браузер сам выбирает файл.
- **Размеры** задаются на вкладке «Изображения». По умолчанию 720 × 480 и 1200 × 800; демо-сайт ставит 16 : 9 — 720 × 405 и 1200 × 675.
- **Кэш** — папка `img/` в корне сайта (настраивается). После смены размеров старые превью можно удалить: новые создадутся при первом заходе.

## SEO и микроразметка

SEO-движок шаблона (`php/Seo.php`) включается на вкладке «SEO и микроразметка».

- **Canonical — по адресу самой страницы**, как у Aimy Canonical и плагина «Система — SEF» ядра: страница указывает на себя, адрес приведён к одному виду — домен и протокол (настройка «Canonical: домен и протокол»), без `/index.php`, без меток вроде `utm_*` и `fbclid` (сохраняются только параметры из настройки «Canonical: параметры адреса», по умолчанию номер страницы `start`). Если canonical уже поставило другое расширение, шаблон берёт его за основу — тег на странице один. Страница с `noindex` canonical не получает. Неразобранный адрес `index.php?option=…` переводится в ЧПУ.
- **Режим «Склеивать адреса материала»** — для статьи, которую открывают по нескольким адресам: canonical указывает на адрес, который строит роутер, но только если он кончается алиасом этой статьи и не ведёт на корень. Списки, метки и пункты меню всегда указывают на себя.
- **Дубли адресов** лучше убирать перенаправлением: включите «Строгую маршрутизацию» в плагине «Система — SEF». Карточка «Состояние шаблона» показывает, включена ли она.
- **OpenGraph и Twitter Card** — заголовок, описание, картинка 1200 × 630 из материала или по умолчанию.
- **JSON-LD** — единый `@graph`: Organization (или выбранный тип), WebSite с SearchAction, BreadcrumbList, Article или NewsArticle, CollectionPage и ItemList для блогов и меток, Person для авторов.
- **Заголовок страницы** — без задвоения «Новости | Новости | Сайт».

Если на сайте стоит SEO-расширение (4SEO, JSitemap, Aimy Canonical и т. п.), выключите движок шаблона или его canonical, чтобы разметка не дублировалась. Плагин ядра «Система — Schema.org» включён в Joomla по умолчанию и добавляет второй граф JSON-LD: выключите его или «JSON-LD» шаблона — карточка «Состояние шаблона» предупреждает об этом.

## Пустая страница com_blank

com_blank ничего не выводит сам: страница собирается из модулей позиций. Шаблон добавляет пункту меню вкладку «Опции WMARKA»:

- вводный абзац, обложка и текст страницы (редактор);
- ширина колонки текста и выравнивание.

Штатный «Показывать заголовок страницы» работает. Если поля пусты и заголовок выключен, шаблон не рисует под компонент пустую секцию. Для главной из модулей поставьте в «CSS-класс страницы» токен `wm-blank`.

## Дочерний шаблон

Свою доработку держите в дочернем шаблоне, а не в самом wmarka: тогда обновления шаблона её не затрагивают.

**Как создать штатно.** **Система → Шаблоны сайта → wmarka (подробности и файлы) → Создать дочерний шаблон**. Ядро Joomla сделает папку `templates/wmarka_имя`:

- манифест — копия родительского без `languages`, `media`, `files`, `update`, с `<inheritable>0</inheritable>` и `<parent>wmarka</parent>`;
- папка `html/` — для переопределений;
- медиапапка `media/templates/site/wmarka_имя/` с `css`, `js`, `images`, `scss`.

**Что класть в дочерний шаблон:**

| Что | Куда | Как работает |
|---|---|---|
| переопределения | `templates/wmarka_имя/html/…` | Joomla ищет их сначала у дочернего шаблона, потом у wmarka |
| свои стили | `media/templates/site/wmarka_имя/css/user.css` | подключается вместо родительского `user.css` |
| свой скрипт | `…/js/user.js` | вместо родительского |
| заглушка, аватар, фавиконки | `…/images/placeholder.jpg`, `…/images/avatar.svg`, `…/images/favicon/` | шаблон ищет их сначала у дочернего |
| партиал шапки, подвала, блоков | `templates/wmarka_имя/partial/имя.php` | `Helper::partial()` возьмёт файл дочернего шаблона, если он есть |

Пример — `wmarka_vestnik` из пакета демо-сайта. Стиль дочернего шаблона хранит свои настройки; у него те же вкладки, что у родителя.

Языковых файлов у дочернего шаблона нет — так его создаёт ядро. Строки `TPL_WMARKA_*` шаблон загружает от родителя сам.

Форму стиля дочернего шаблона Joomla строит по его собственному манифесту — копии настроек родителя на день создания. Поэтому при каждом обновлении wmarka переносит свои поля во все дочерние шаблоны (`<parent>wmarka</parent>`): новые дописывает, прежние заменяет своей версией. Поля, которые есть только у дочернего шаблона, остаются как были. Без этого первое же сохранение стиля дочернего шаблона стёрло бы значения новых параметров.

## Свои стили и скрипты

- `media/templates/site/wmarka/css/user.css` и `js/user.js` создаются при первой установке и **никогда не перезаписываются** обновлением. Пишите туда свои правила, если не пользуетесь дочерним шаблоном.
- `css/wmarka.css` — мост разметки ядра и оформление цитаты. Он обновляется вместе с шаблоном, править его не нужно.
- Капс UIkit снимает `css/nocaps.css` (настройка «Строчные надписи»).

## Обновление

Обновление безопасно для сайта:

- `user.css` и `user.js` не перезаписываются;
- настройки стиля сохраняются; новые параметры получают значения по умолчанию;
- языковые переопределения 3.0.x продолжают работать как запасной источник;
- удаляются файлы прежних версий, которые иначе перехватили бы новый вывод: `html/pagination.php`, `html/modules.php`, старые макеты меню, отдельные партиалы блоков.

Перед обновлением рабочего сайта сделайте резервную копию — это правило для любых расширений.

## История шаблона

**Корни.** Wmarka вырос из стартовых шаблонов Joomla с «чистой» разметкой. Как сказано в описании версии 3.0, философия чистоты взята у заготовки **J!Blank** (без генерации LESS и SASS), а схема позиций — у шаблона **Master3**. Оформление с самого начала строилось на **UIkit**, обработка изображений — на библиотеке **JUImage**.

**3.0.0 (29 марта 2026)** — первый публичный релиз для Joomla 5 и 6:

- PHP 8.3, UIkit 3, обязательная JUImage с WebP;
- блоки сайта вынесены в партиалы (`partial/`);
- переписаны com_content, com_tags (с деревом меток), com_finder, com_contact, com_blank, часть модулей;
- микроразметка Schema.org и OpenGraph, но данные организации задавались **языковыми переопределениями** (`TPL_WMARKA_SEO_*`), а размеры превью — правкой файлов макетов;
- режим прототипирования: пустые страницы заполнялись заглушками.

**Внутренняя ветка 3.0.1–3.0.26 (лето 2026).** Сборки обкатывались на сайте TAMGARD PARTNERS: аудит под Joomla 6, мегаменю на токенах, SEO-движок с JSON-LD `@graph`, макеты авторов и команды, формы на UIkit, мобильный аудит. Ветка была сведена в один выпуск.

**4.0.0 (октябрь 2026)** — первый публичный выпуск после 3.0.0, собранный заново:

- все настройки — в админке, в девяти вкладках;
- единый сервис изображений: одно превью на картинку;
- UIkit 3.25.25;
- переопределения всех модулей и основных компонентов;
- исправленная структура пакета.

**4.0.1–4.0.13** — сверка оверрайдов с оригинальными макетами Joomla, дозированные анонсы, srcset, карточки на компоненте Card, новостная подача, мегаменю на карточках, дочерний шаблон по правилам ядра, полная демо-установка. Подробно — в [CHANGELOG.md](CHANGELOG.md).

## Частые вопросы

**Картинки не режутся, выводятся оригиналы.** Не установлена JUImage или она выключена на вкладке «Изображения». Карточка «Состояние шаблона» показывает, найдена ли библиотека.

**Вместо текста видны ключи `TPL_WMARKA_…`.** Языковые файлы шаблона не установились: переустановите шаблон тем же архивом.

**Поиск ведёт на 404.** Включите ЧПУ и `.htaccess`, создайте пункт меню «Умный поиск» и выберите его в «Пункт меню поиска». Индекс обновляется командой `php cli/joomla.php finder:index` или в «Умный поиск → Индексировать».

**Как сделать модуль во всю ширину?** Опубликуйте его в блочной позиции и выберите стиль `blank`. Модуль должен сам задать секцию, например `<section class="uk-section uk-section-muted"><div class="uk-container">…</div></section>`.

**Мегаменю не появилось.** Проверьте токен в «CSS-класс ссылки» именно у пункта первого уровня и то, что вспомогательное меню опубликовано и в нём есть пункты первого уровня.

**Модуль в колонке мегаменю не виден.** Он должен быть опубликован, привязан ко всем страницам и стоять в любой позиции (например `mega`). Токен — `wm-mod-ID` у пункта-колонки.

**Можно ли без com_blank?** Да. Главную из модулей можно собрать на любом пункте меню с токеном `wm-blank` в «CSS-класс страницы».
